# 넥슨 오픈 API 제약사항

## Rate Limit
- 개발단계 API Key: 초당 5건, **일일 1,000건** (모든 엔드포인트 합산, 애플리케이션/Key 단위 — 계정 전체 합산인지는 미확인)
- 매치 기록, 선수 상세 능력치, 유저 정보 조회 등 모든 API 호출이 같은 한도를 공유한다.
- 게임당 애플리케이션 최대 3개, 애플리케이션당 API Key 최대 2개까지 등록 가능
  (실제로 여러 앱/키를 쓰면 한도가 개별로 잡히는지는 미확인 — 실측 필요).

## 한도에 안 걸리는 예외
- `spid.json` (선수 고유 식별자 정적 파일): Key 없이 무제한 다운로드 가능. 이름/포지션 검색용으로 활용.

## 주요 엔드포인트
| 목적 | 엔드포인트 | 비고 |
|---|---|---|
| 닉네임 → ouid 변환 | `/fconline/v1/id?nickname=` | |
| 매치 목록 조회 (matchId 확보) | `/fconline/v1/user/match` | 파라미터: ouid, matchtype, offset, limit(최대 100) |
| 매치 상세 조회 | `/fconline/v1/match-detail` | 파라미터: matchid |
| 선수 포지션 메타데이터 | `/metadata/spposition` | 28개 코드, 좌/중앙/우 세분화됨 |
| 매치 타입 메타데이터 | `/metadata/matchtype` | 사용할 코드(공식경기) 확정 필요 |

## 매치 목록 조회 시 주의
- `limit` 최대 100 — 그 이상 필요하면 `offset`을 100 단위로 늘려가며 반복 호출.
- 승률학습용 트랙은 `limit=1`만 사용 (1유저 1경기, 스노우볼 방식).
- 스타일진단용 트랙은 `limit=100`까지 사용 가능.

## 랭킹/닉네임 확보
- `RankerStats` 엔드포인트는 선수별 평균 통계만 제공 — 닉네임/순위 목록은 아님.
- 별도 "닉네임 목록" 제공 오픈API는 확인되지 않음 → 매치 상세 조회의 `matchInfo` 내 상대방 정보로
  스노우볼 방식 확장 사용 (CLAUDE.md 참고).
